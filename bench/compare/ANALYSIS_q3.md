# q3 analysis plan

Written before any system ran on q3. q3.json is frozen (FREEZE_q3.txt, sha256 9cfcbea0...c692, 2026-11-14 01:23:43 UTC). This file's own hash and the time are in ANALYSIS_q3.sha256, written by the same command that hashed it. After that line exists I do not edit this file; a later change goes into a new dated file that says what changed and why.

## What runs

Each of the ten configurations runs once on q3.json with the adapter, settings and version it had in runs2:

| run name | what it is |
|---|---|
| bm25 | plain BM25 baseline from the LEKS benchmark harness |
| leks | LEKS 3.1 as published (rel 906e898, public main 863bc23), words only |
| leks30 | LEKS v3.0.0, words only |
| leks-models | LEKS 3.1 with the models extra (mDenseOn and mLateOn) |
| qmd__search | qmd 2.8.3, keyword search |
| qmd__vsearch | qmd 2.8.3, vector search |
| qmd__query | qmd 2.8.3, query expansion, fusion and reranking |
| mempalace__default | MemPalace 3.12.0, default search |
| mempalace__hybrid | MemPalace 3.12.0, hybrid search |
| knowledge-rag__hybrid | knowledge-rag 5.0.1, hybrid search with its reranker |

The scripts are harness/q3_sandbox.sh and harness/q3_terminal.sh. A failed run is reported with its reason. I repeat a run with unchanged settings only after an infrastructure failure (a crash, a full disk, a killed process) and write the repeat down. If the review of runs2 finds a harness error, I fix it and record the fix before q3 starts. No setting of any system changes because of a q3 number.

## Measures

- hit@5 is the primary measure; hit@1 and MRR@10 are secondary and descriptive.
- The top 10 counts, and a copy of the gold note counts as the gold note, the same rule as runs2.
- Every rate gets a Wilson 95% interval.
- q3 is reported on its own and never pooled with q1, q1p or q2.

## Paired tests

Exact McNemar on hit@5, question by question, with one Holm correction over these 16 comparisons:

- leks-models against bm25, qmd__search, qmd__vsearch, qmd__query, mempalace__default, mempalace__hybrid and knowledge-rag__hybrid (7 tests)
- leks against the same seven (7 tests)
- leks-models against leks (1 test)
- leks against leks30 (1 test)

## Wording rule for the public page

- "Better" or "worse" only where the Holm-adjusted p is below 0.05 on q3. Otherwise the page says the difference is within what these 695 questions can separate.
- The q1p result for the same pair stands beside it as a consistency check, without a test.

Every configuration appears in the tables, including the ones where LEKS loses.

## Time and memory

- The cost table (median and p95 time per question, index time, peak memory) comes from runs2: 1,472 questions, one run at a time.
- q3 timings are recorded. They are reported only for runs that no other run overlapped, and the page says which.

## Limit written before the data

q3 has one gold note per question: the note whose abstract the question was written from. When another note also answers the question, a system that ranks that note first loses the point, so absolute rates are lower bounds, and a system that leans to related notes can lose more than one that matches words. To size this, I draw 20 misses at hit@5 for leks-models and 20 for the best competitor configuration on q3 hit@5, with `random.Random(20261114).sample(sorted(miss_ids), 20)`, and report how many have a top hit that also answers the question, with the rule: the top hit's title or abstract states what the question asks for.
